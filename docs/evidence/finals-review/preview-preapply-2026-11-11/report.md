**F1 — P1: `response.body()` can silently refetch or accept an empty substitute, invalidating original-response coverage.** `deployment/finals/preview/qualify.ts:108` calls the high-level Playwright body API, scans the returned bytes and unconditionally marks that request covered. The locally pinned Playwright1.65.0 Chromium implementation in `node_modules/.pnpm/playwright-core@1.65.0/node_modules/playwright-core/lib/coreBundle.js:38181` first calls `Network.getResponseBody`. When that returns an empty body despite nonzero Content-Length, line 38202 can call **`Network.loadNetworkResource` with credentials**, then return the later fetch's bytes. This applies to its listed font/image/manifest/media/script/stylesheet/texttrack types and prefetches; some other branches instead return an empty buffer at lines 38194–38200. The qualifier has no check distinguishing these returned substitutes from the original delivered entity. It can report exact coverage while scanning replacement or empty content, contrary to the packet's explicit no-later-GET/body-ownership requirement. This is an inspected conditional failure path, not an observed remote leak or assertion that every response refetches.

**Minimal fix:** use an original-response capture operation whose pinned implementation cannot refetch, retain its request/response identity, and reject missing or unjustified empty bodies. Preserve status/body ownership through navigation. The same dependency's `internalBody()` at line 14885 waits for lifecycle completion and explicitly warns that navigation can make bodies unavailable; the new gate also lacks a request-failure completion path for its coverage map. TASK-019's separate proxy-finish evidence does not transfer to this native HTTPS body API. The repair must keep missing/canceled/redirect/204 handling honest and fail closed when original entity ownership is unavailable; it must not relabel absent CDP events or add a replacement GET. A focused original-body/no-refetch regression is appropriate for the writer before binding the repaired gate.

**F3 — P2: HTTP login validation can throw before the new session is registered for cleanup.** In `qualify.ts:74–76`, body scanning/status/no-store assertions can throw before the login response reaches its caller.
