## Verified hosting behavior and constraints

Render Free supports web services and Postgres, not private/background workers. It sleeps after15 idle minutes, wakes in roughly1 minute, and loses filesystem changes on restart/sleep/deploy. Worker ingress therefore needs public HTTPS authentication; queue/nonces/reservations belong in SQL. Free provides750 instance-hours/workspace/month; exhaustion suspends services. Bandwidth/build overages can bill when payment exists or suspend/block builds without it. A free DB is limited to one active instance/workspace,1GB, expires after30 days, then has14 days before deletion; no backups or managed pooling. Account-specific creation/verification/remaining quota is unknown. [Official Render free-service rules](https://render.com/docs/free).

Free cannot use paid pre-deploy commands; migration needs a controlled external TLS execution before traffic. Render web must bind `0.0.0.0`/`PORT`; current worker default is loopback, so explicit host config is essential. [Blueprint deployment lifecycle](https://render.com/docs/blueprint-spec), [web binding rules](https://render.com/docs/web-services). Render supports PostgreSQL17 creation; external DB connections require TLS. Vercel needs external DB access while Render worker can use the same-region internal URL. [Postgres connection documentation](https://render.com/docs/postgresql-creating-connecting).

Vercel offers Node major selection and automatically changes minor/patch versions, so24.x is compatible deployment family, not proof of exact24.22.1 runtime. Record actual build/runtime when deploying. Root/outside-root settings are required for shared monorepo source. [Node runtime policy](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions), [monorepo settings](https://vercel.com/docs/monorepos).
