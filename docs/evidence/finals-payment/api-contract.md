# TASK-005 backend contract (updated 2026-11-10)

Work ref: `orca:run_3bfef6dba661/payment`. This describes implemented code, not a hosted or full-model release. Canonical API intent remains in `docs/api-spec.md`; model execution is TASK-007.

## Application and security boundary

`createApplication({store, env, wallet, wake?})` in `src/server/http/application.ts` accepts a standard `Request` and returns `Promise<Response>`. The existing Next catch-all adapter uses this application. JSON/error responses are `no-store`; timestamps are ISO strings, amounts/nonces decimal strings, nullable observations remain null. Errors have `{error:{code,message,correlationId}}` with fixed safe messages. No SDK/provider error, signed agent envelope, ciphertext or secret is returned.

Browser clients use the existing HttpOnly session cookie and exact configured Origin for mutations. Model tools should receive an opaque worker bearer created internally with `issueSession(store,{role:'worker',ownerId,runId})`; it lasts 15 minutes, is scoped to that run, and must never be exposed to a browser/model prompt or logged. The trusted tool executor can hold it and make requests. Cross-owner/run lookups return 404; merchants cannot purchase or read owner receipts.

`GET /api/v1/state` remains the existing owner/merchant read model. Owner `attempts` expose safe status/quote/operation/inner/outer/Velo request/error fields; the independent attempt endpoint adds receipt ID. Policy/escrow values must be refreshed through the existing authenticated wallet-state endpoint; minimal health is liveness, never proof of current payment/model readiness. `POST /api/v1/runs` queues a run and `GET /api/v1/runs/:id` reads it, but TASK-005 consumes only reconcile jobs: do not represent queued runs as model execution. Run events remain TASK-007 work.

After the November 10 review fixes, owner `state.agent` has exactly `id`, `publicKey`, `deviceHash`, `network`, `deviceContractId`, `agentContractId`, `escrowContractId`, `assetContractId`, `status`, `policyMaxStroops`, `policyExpiresAt`, `policyObservedLedger`. It omits lease owner/deadline, owner FK, nonce bookkeeping and creation metadata. Wallet refresh and human-wallet confirmation refresh policy observations without re-enabling an operator-disabled agent; the current SQL row's disabled decision wins over an earlier RPC snapshot. New run creation and quote acceptance remain denied while disabled; identity-only reconciliation of a prior handoff and safe wallet recovery remain available.

Attempt `errorCode: 'PAYMENT_EVIDENCE_CONTRADICTION'` with `status: 'manual_review'` means an allowlisted internal identity/invocation/evidence guard rejected deterministic bindings. It preserves reservation/nonce/hashes/handoff and held budget; it is not permission to retry payment. Missing chain/event data and transport failures remain `unknown` with fixed unavailable codes. A final ownership read that consumes the remaining quote window before first submission records `manual_review` / `POST_HANDOFF_QUOTE_EXPIRED`; its saved handoff and held budget remain, with no submission or automatic grant on subsequent executor calls. Ordinary independent confirmation after an actual timely submission remains eligible for verified authorization. No new public mutation or repair endpoint is introduced.

## Worker entrypoints

`startWorker(env)` in `apps/server/src/index.ts` starts a long-lived Node consumer and authenticated wake ingress. Configure `PORT` and `WORKER_HOST=0.0.0.0` on Render; loopback is the local default. It returns an async shutdown function that waits for active work and closes SQL. `GET /health` is minimal liveness; `POST /wake` requires a long random `WORKER_WAKE_TOKEN`, machine bearer authentication, no Origin, content-type JSON and exactly `{}` (1 KiB streamed limit). It accepts no financial input. Web only needs the wake URL/token, DB/network/public addresses and receipt key; signing/Velo/encryption/model keys remain worker-only.

`paymentConsumer({store,adapter:()=>Promise<PaymentAdapter>,key,receiptHash})` exposes `wake()` and `idle()`. It leases only `reconcile` jobs with SQL `FOR UPDATE SKIP LOCKED`, fences completion by original lease owner/deadline and requeues observations with bounded delay. Model workers must implement a separate `run` consumer rather than accidentally leasing payment work.

`processPayment(store, attemptId, adapter, key, receiptHash)` is internal worker code. `PaymentAdapter.prepare({quote,attempt,agent})` returns exact signed envelope/inner hash **inside worker memory only**; `gas` has installed Velo 1.0.0 sponsor/submit/getStatus methods; `verify({...snapshot,execution})` returns an independently checked `VerifiedObservation`. Production uses `createLivePaymentAdapter(env,store)`, not the synthetic integration helper. Test-only fault hooks must never be exposed through HTTP/config/model tools.

`observationOnly(adapter)` returns a payment adapter whose prepare/sponsor/submit methods always refuse with fixed `OBSERVATION_ONLY`. It permits only identity status and independent verification, so internal recovery callers can pass it to `processPayment` after checking a saved handoff. It never converts missing chain data, a provider conflict or policy expiry into terminal failure. The long-lived server caches its successfully verified live adapter; observation polling does not repeat full deployment verification.

The executor reserves using SQL domain APIs, encrypts exact signed bytes before sponsorship, saves validated Velo reservation before the exclusive handoff marker and deletes ciphertext at handoff. There is exactly one application submit call with SDK retries disabled. After the marker all restarts observe the original identity; unknown/manual-review holds budget and grants nothing. Live preparation additionally verifies configured deployment, current policy/device/asset/escrow and durable nonce continuity. The final evidence/entitlement/spend commit requires the worker ownership fence. Merchant claim remains a separate human-wallet flow.

`wallet-inspection.ts` is a pure shared server verifier; domain wallet code no longer imports the spike journal transitively. The CLI alone imports disposable setup/journal helpers. Do not import the private `merchant/reports.ts` fixtures into client/public modules, and do not expose any proof-ingest or success-flag route.

## CLI integration

`pnpm purchase:smoke --preflight` performs real read-only configured deployment/DB/device/policy/escrow checks. Missing prerequisites fail with names/codes and exit 1. `--setup` is an explicit opted-in disposable Testnet owner setup, preserving the historical spike directory and DB; it creates a separate device in `.aegispay-spike/finals-payment-005`, imports independently verified registration proof, seeds metadata and writes worker-only local configuration. It does not authorize a paid report.

`--execute` deliberately accepts one 300000-stroop QuickSignal quote through the actual application Request/Response interface and processes it through the actual PostgreSQL worker/SDK adapter. Its append-only CLI checkpoints preserve the original run/quote/acceptance keys; rerunning resumes that identity. It requires both evidence sources, a gated report read and exact escrow/pending deltas. Reports export only safe decoded proof/IDs/deltas, never report body, receipt token, XDR or credentials. This exercises the backend abstraction in process; it is not browser/hosted HTTP or model acceptance. Current observed outcomes and unrun gates belong in `task-005.md`.

`--observe` is the explicit recovery gate: it requires the original CLI attempt/run/quote/keys and a persisted reservation/inner hash/handoff, checks their DB relationships, skips quote issuance and acceptance, and uses `observationOnly`. Expired current policy never blocks observation of a timely original dispatch. Matching success still has to pass the actual verifier and atomic grant before any report is read. It exits 1 `PAID_RESOURCE_GATE_UNRESOLVED` if the bounded window ends unresolved; a successfully completed observation command alone is not a paid-resource pass. With the current unknown attempt, do not run `--setup`, create a replacement quote/fixture, or make a new financial dispatch.

`node --env-file-if-exists=.env.worker.local --import tsx scripts/purchase-observe.ts` is a separate diagnostic, with no signer/sponsor/submit/grant path. It reads the saved attempt checkpoint, allowlisted DB fields, original Velo identity status, original inner RPC transaction and current escrow/pending balances. Its JSON artifact explicitly says observation-only; exit 0 means diagnostic collection succeeded, even when the payment remains unknown. No endpoint exposes either CLI function.

Receipt `evidence` currently contains `id`, `attemptId`, `innerHash`, `outerHash`, `observedEventTxHash`, `noirEventId`, `network`, `contractId`, `ledgerSequence`, `ledgerClosedAt`, `agentPublicKey`, `deviceHash`, `merchantAddress`, `assetContractId`, `amountStroops`, `nonce`, `actualFeeStroops`, `feeProvenance`, `evidenceDigest`, `verifiedAt`. JSON decimal strings represent ledger/amount/nonce/fee; nullable fee/outer hash stay null. `feeProvenance` is `outer_ledger_and_velo` only for independently equal values, otherwise `unavailable`. Resource report content is returned only by the authorized resource route, never the metadata/catalog/state response.
