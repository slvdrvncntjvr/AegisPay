02 / THE PROBLEM
WORKFLOW HYPOTHESIS
A new data source should not require
open-ended payment authority.
For a small agent team, the useful unit to test is one task, one quote and one auditable purchase.
DEVELOPER
“Get the useful report.”
The agent may discover a paid resource
while working. Its owner still needs a
finite budget and expiry.
API PROVIDER
“Prove this purchase.”
A payment must match the merchant,
amount and quoted resource before
protected data is released.
WHEN STATUS IS UNCLEAR
“Did it already pay?”
A timeout must preserve identity. A
second signature or blind submission
can create another charge.
Prepaid API keys can work well. We are testing whether bounded, per-request wallet purchasing improves this specific workflow. Demand and
pricing are unvalidated.
